# 离线交接

## 为什么

本机会话在电脑睡眠或关机时停止，正在跑的子代理也一起停。云端会话不会向本机回报，它结束时没有通知。交接时没写下来的东西，对接手的一方就不存在。

## 做法

1. **先提交并推送。** 云端从仓库的默认分支开始，本机没推送的改动它看不到。
2. **把正在进行的工作落到仓库里的固定位置。** 例如还在跑的评审，结果回来后存到约定的目录并推送；在给云端的任务说明里写明"开始下一步前先拉取，这个目录里有内容就并入，不要重做"。
3. **任务说明要自足。** 接手的一方没看过这段对话。写清：目标、已定的决定和用户此前的选择、硬性约束、交付顺序、完成的标志、额度不够时先保什么。
4. **写明它没法提问。** 需要用户本人的事，记下来继续做别的，不要停。
5. **约定交接文件。** 让它在分支里写一份"需要用户回来后在本机做的事"，每项带可以直接运行的命令。常见的有：填密钥后的在线测试、在本机浏览器里走查、合并、需要本机硬件或登录状态的步骤。
6. **约定产出的形式**：单独的分支加一个不合并的合并请求，描述里写做了什么、测试数字、没做和没验证的。

## 用户回来之后

- 云端不回报，所以先看远端：有没有新分支、最后一次提交的时间、合并请求和交接文件。没有新分支不等于失败，可能还在装环境。
- 云端的结果和子代理的报告一样对待：拉到本机，重新跑测试，在真实入口走一遍，再告诉用户可以合并。
- 把交接文件里的项目和本机这边攒下的项目合成一张清单给用户，一次说完。

## 规则

- **不替用户处理密钥。** 密钥由用户自己填进本机的配置文件，交接文件里只写变量名和要运行的命令。
- **不能验证的事不写成已完成。** 例如在线模型没有真实调用过，就在每一次总结里都这样写，直到它被验证。
- 只在用户要求时才把工作挪到云端。
