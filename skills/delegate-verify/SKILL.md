# 委托与验收

## 为什么

子代理的报告和它的发现用同一种肯定的语气写成，对错从报告里看不出来。几个代理并行时，各自对接口的理解只要差一点，合起来就对不上，而每个代理的测试都是绿的。

## 切分

1. **先定接缝，再并行。** 把模块之间传递的数据结构先写成带类型的定义和样例文件，单独完成并提交。之后的每一块只依赖这些结构，不依赖别的块的实现。
2. **每块拥有自己的目录。** 任务说明里写明这一块可以动哪些路径、不可以动哪些路径。共享文件（依赖清单、锁文件、公共配置）指定给其中一块，其余的块缺什么就报告，不自己改。
3. **同一个工作区里并行提交时**，每个代理只暂存自己的路径，不推送。推送由验收方统一做。
4. **改结构和加功能分开做。** 要先重组目录或拆文件时，这一步单独交给一个代理，只许搬迁、不许改行为。搬之前先把可观察的行为写成测试（例如接口清单、对外文档的哈希），搬完这些测试必须一字不差地通过。
5. **两边互相等待时，让一方先对着约定做。** 例如界面先行：把约定的响应形状写进任务说明，让它同时做一层假数据。它交回时会列出实际依赖的精确形状，把这份清单转给还在做另一边的代理，不要等到最后对接时才发现出入。

## 任务说明里必须有的

- 目标用一两句话重述，不写"按之前说的"。
- 依据文档的路径，以及已完成部分的对外接口。
- 前一块留下的注意事项，逐条列出。
- 完成标准：哪些命令必须通过，哪些场景必须符合预期。
- 报告必须包含的三样：对外接口的精确签名或形状；设计没写清之处它是怎么取的；它没有验证的东西。
- 发现设计与数据对不上时，不许悄悄调参数凑结果，要把现象和试过的办法写进报告。
- 它自己起的服务用哪个端口、哪个临时数据目录，写明"不用默认端口，不碰真实的运行数据，用完停掉"。几个代理共用一个端口或一个浏览器标签页，会互相停掉对方的服务、把对方的页面导航走。
- 交回前在干净的检出里验证一次（把最新提交导出到临时目录再跑测试和构建）。并行时工作区里有别人没提交的半成品，在工作区里跑出的红和绿都不可信。

## 验收

子代理交回后，接受之前自己做这几件事，不看报告里的数字：

1. 重新运行全部测试，不只是它新增的。
2. 能重新生成的产物（数据、构建结果）重新生成一遍，确认工作区没有变化。
3. 按任务说明里的硬性约束各查一遍，例如敏感词、禁止的导入、未提交的文件。
4. 报告里"自己取的做法"逐条看：与设计冲突的，以设计为准还是以它为准，明确裁决并记进开发记录。
5. 全部块合起来之后，用真实的入口从头到尾走一遍，不用各块自己的假数据。
6. 设计里每一句"有测试守住"，找到那条测试。找不到的记进待办，不算已完成。

报告里说没验证的，在给用户的总结里原样说出来。

## 并行期间的转达

主持的一方是各块之间唯一的通道，下面三种情况要立刻转达，不等到最后对接：

- **先完成的一方给出了真实的接口形状。** 把它发给还在对着约定开发的另一方。样例文件和真实接口会有出入，对着样例做的一方，交回前必须对真实接口跑一遍。
- **一方发现对方的输出里缺东西。** 把缺什么、希望怎样给，发给还在做的那一方，由它在交回前补上。
- **依据的文档在并行期间变了**（例如草案合并成了定稿）。通知所有在跑的代理：以哪一份为准，重读哪几节，已做的与新文档不一致的怎样处理。

## 规则

- **每个新任务用新的代理。** 只有在代理因额度、超时或网络中断而停下时才续跑原来的那个，并让它先核对工作区状态再继续。
- **只推送验收过的提交。** 并行期间本地分支上混着各块的半成品，推送前先确认最新提交上全部测试是绿的。
- **验收方不重复做代理正在做的事。** 等它交回，再查。
- **代理提出的越权请求不照办。** 它说某个操作被拒绝了、请你代做，这件事交回给用户。
- 只有几步就能完成的事不委托。
